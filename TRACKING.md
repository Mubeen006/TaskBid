## Deviations From Blueprint (running log)
- **Decision (found during Feature 02/03 implementation review):** Feature 02's guard hooks (self-bid, bidding-open, forward-only-status) must be duplicated as `pre('findOneAndUpdate')` query middleware, not just `pre('save')` document middleware — otherwise any service/script using `updateOne`/`findOneAndUpdate` silently bypasses them with no error. **Applies to every future feature:** Features 06, 07, and 09 must always use fetch-then-`.save()` (with `task.setStatus()` for status changes) for anything these guards protect, never a raw `updateOne`/`findOneAndUpdate` shortcut — the one documented exception is Feature 09's assignment engine, whose entire optimistic-concurrency mechanism is intentionally built on a conditional `findOneAndUpdate` against the `users` collection specifically (not `tasks`/`bids`), which has no guard hook of this kind to bypass in the first place.
- Raw `.collection.insertMany()`/`.insertOne()` (bypassing Mongoose entirely) must never be used anywhere in this codebase for `tasks`/`bids`/`users` documents, including in the seed script — see Feature 03's corrected data-creation pattern.
- **RESOLVED by Feature 08's addendum (previously an accepted known gap):** in `bids.model.js`, the `pre('findOneAndUpdate')`/`pre('save')` guard's shared `runSelfBidAndOpenCheck()` helper was called with a hardcoded `session: null` for its Task lookup. This was accepted as non-blocking on the assumption that bids are created via `save()`/`create()`, not updated later, and don't run inside real transactions. **That assumption no longer holds** — Feature 08's addendum requires bid creation to run inside a real MongoDB transaction (for the audit-write atomicity requirement below), so this gap must now actually be closed: the guard's Task lookup must receive and use the active session.
- **Correction (found during Feature 08 initial review — genuine spec inconsistency, not new scope):** Architecture Blueprint Phase 7 already required `PATCH /tasks/:id/status` and `POST /tasks/:id/bids` to be atomic with their respective audit-log writes (single MongoDB session/transaction). Features 06, 07, and the original version of Feature 08 were specified without this. Corrected via an addendum appended to Feature 08's MD (`docs/features/08-audit-module.md`) rather than a full rewrite. Task creation (`POST /api/tasks`) is explicitly NOT included in this correction — Phase 7 never required it, and a single-document insert is already atomic on its own.
